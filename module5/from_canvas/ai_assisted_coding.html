Mindset Layer — Your Role and Attitude

1. Plan before you code
AI can't design what you haven't imagined. Define inputs, outputs, and logic first — you are the architect.

2. Manage your expectations
AI accelerates progress, not perfection. Debugging, reasoning, and problem framing are still your job.

3. Reflect on your partnership
After each session, ask: What did I rely on AI for? What did I still do myself? This self-awareness builds independence and better judgment.

Process Layer — How You Work with AI

1. Frame each task with intention and prompt
Before writing any code, separate what you want from how you'll get it:

  • Intention: What you want to achieve and why it matters
  • Prompt: How you'll communicate this to AI (or implement it yourself)

This separation keeps YOU in the driver's seat of problem design.

Example:

Task 4. Understand the data structure and types
* Intention: Learn the schema and null counts to assess data quality
* Prompt: Call `.info()` on the games DataFrame to view column data 
  types and non-null counts

2. Let AI take small steps
Build incrementally. Ask for one function or fix at a time, test it, then expand.

What this looks like:

  • ✅ "Write a function to calculate the mean of column X"
  • ❌ "Build a complete data pipeline with cleaning, analysis, and visualization"

3. Verify the code
Fluent ≠ correct. Run, test, and explain what the code is doing before trusting it.

Ask yourself: Can I explain this line-by-line? Do I understand what would happen if the input changed?

4. Iterate like a scientist
Treat coding as hypothesis testing: Predict → prompt → test → reflect → adjust.

5. Audit for bias and brittleness
Ask: What assumptions does this code make? AI may encode shortcuts that fail in edge cases — test for them early.

Common edge cases to check:

  • Empty datasets or missing values
  • Unexpected data types
  • Extreme values (very large/small numbers)
  • Different operating systems or environments

Communication Layer — How You Talk to AI

1. Explain your intent
Treat AI like a teammate, not a tool. Describe what you want, why you want it, and how it fits into your larger goal.

Compare:

  • ❌ "Make a plot"
  • ✅ "Create a scatter plot showing the relationship between price and sales volume to identify potential outliers before running regression"

2. Spell out names clearly
Use descriptive variables and objects. AI relies on context — clear names make its reasoning (and your debugging) smarter.

Compare:

  • ❌ create a df to store customer purchases information
  • ✅ customer_purchases, monthly_revenue, cleaned_data

 

3. Own the context
AI doesn't know your project boundaries. Remind it of data types, dependencies, and runtime limits often.

Include in your prompts:

  • What libraries you're using
  • Size/shape of your data
  • Any constraints (memory, time, formatting requirements)

 

4. Document as you go
Use AI to help write comments, docstrings, and commit messages. You'll understand your own logic better — and others will too.

5. Learn from the AI
Don't just accept code — reverse-engineer it. Ask: Why did it do this? What pattern is it using? Turn every output into a lesson.

Mistakes to Avoid

Mistakes Why it happens How to fix it
Copy-paste without understanding AI code looks professional Always explain it line-by-line before using
Asking for too much at once Trying to save time Break into smaller, testable pieces
Not testing edge cases AI shows typical cases only Manually test with: empty data, nulls, extremes
Treating AI as oracle The code runs = it's right Verify logic, not just syntax
Repeating failed prompts Hoping for different results Rephrase with more context or constraints (remember the intention—prompt framework)
